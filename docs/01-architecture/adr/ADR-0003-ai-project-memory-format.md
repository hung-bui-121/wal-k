# ADR-0003 — `.ai/` Project Memory Format

**Status:** Proposed (owner confirmation required before Stage 1)
**Date:** 2026-10-05
**Deciders:** Project owner, system architect

## Context

§34–§35 require repository-local persistent memory under `.ai/` with a suggested layout but "exact structure remains implementation-specific"; §139 lists "Markdown vs YAML vs JSON for `.ai`" as open. §42 requires freshness stamps (commit, PR, version, timestamp) and a CURRENT / POSSIBLY_STALE / INVALID classification. §36–§38 enumerate section content for project, feature and bug context. §33 requires approved artifacts to be first-class and non-driftable. ADR-0001 already chose "Markdown with YAML front matter" at the format level; this ADR fixes the concrete layout, naming, header schema and freshness rules.

## Decision

**D-1 Layout and naming** are exactly as in `ARCHITECTURE.md` §8: folders `project/ phases/ features/ bugs/ decisions/ approved/ reports/ handovers/ improvements/ agents/`; documents named `<PREFIX>-<seq>.md` matching the kernel ID (`FEAT-0012.md`); binary payloads in a sibling folder with the same stem (`FEAT-0012/evidence/`). `[MVP]` folders are `project/ features/ bugs/ decisions/ handovers/` (§130).

**D-2 Document = YAML front matter + fixed H2 sections.** The front matter schema is `walk.memory.models.FrontMatter` (`ARCHITECTURE.md` §8.2): `id, type, title, status, version, schema_version, created_at, updated_at, updated_by{role, model_id, run_id}, freshness{commit, branch, timestamp, pr?, build?}, related{work_items, decisions, approved, evidence, gdd}, relevant_files, extra`. Body sections are H2 headings with fixed names per `MemoryDocType`, in the order the spec lists them (§36 project, §37 feature, §38 bug, §22 handover, §44 decision, §33 approved, §98 candidate, §96 observation). Unknown H2 sections are preserved verbatim; `MemoryManager` edits sections individually (`ContextUpdate` REPLACE/APPEND).

**D-3 Freshness stamp = commit SHA + timestamp (+ branch, optional PR/build).** `MemoryManager.write()` stamps `freshness.commit` with the HEAD of the branch the writing run worked on and `freshness.timestamp` with the write time. Classification (`INTERFACES.md` §5.5): stamp commit not an ancestor of HEAD → INVALID; any `relevant_files` missing → INVALID; `relevant_files` changed since stamp → POSSIBLY_STALE; older than `max_age_days` (30) → POSSIBLY_STALE; else CURRENT. Results cached in `memory_index`.

**D-4 All writes go through `MemoryManager.write()`.** It validates the header, bumps `version`, stamps freshness, refuses secret-looking content, refuses writes under `approved/` without a change decision, writes atomically (temp + rename), updates `memory_index`, fires `ON_CONTEXT_UPDATED`. Agents never write `.ai/` directly: `BoundaryAuditor` fails a run whose diff touches `.ai/` except `features/<id>/evidence/` and `bugs/<id>/evidence/`.

**D-5 Approved artifacts** (`approved/APR-NNNN.md` + payload folder) carry `content_sha256` over payload files, `approved_by`, `scope`, `version`, `related_requirements`, `supersedes`, `change_request_decision`. Startup and `walk doctor` verify hashes; mismatch → `ON_CONTEXT_STALE(INVALID)` and the artifact is excluded from context until re-approved (Invariant 10).

**D-6 Reports are generated, overwritable files** under `reports/<kind>/<subject>.md`, produced only from ledger queries (§83); they carry `type: report` and no freshness semantics.

**D-7 Kernel configuration under `.ai/agents/`** is YAML (`policies.yaml`, `models.yaml`, `permissions.yaml`, `hooks.yaml`, `projections.lock.yaml`) except role constitutions and skills, which are Markdown+front matter like other documents (ADR-0013, ADR-0007).

**D-8 `.ai/.gitignore`** (generated by bootstrap) excludes `kernel.db*`, `kernel.lock`; everything else in `.ai/` is committed. `.walk/` at repo root is fully ignored.

## Alternatives

- **JSON documents:** rejected — not reviewable by humans in PRs (§6.2).
- **Pure YAML:** rejected — long narrative sections (architecture, investigations) are awkward in YAML; Markdown sections are natural for LLMs and humans.
- **One big file per folder:** rejected — merge conflicts across parallel worktrees; per-item files map to per-item branches.
- **Freshness by timestamp only:** rejected — cannot detect whether relevant code actually changed; commit-anchored diffs can.
- **Store evidence binaries in git LFS:** deferred; MVP stores small artifacts (screenshots, logs, JSON metrics) in-repo and references large recordings/builds by URI.

## Consequences

- Parallel runs touching the same feature context can conflict at merge; mitigated by section-level edits and `TaskRouter.can_run_parallel` (no two runs on the same feature with overlapping files).
- Every memory write needs a git HEAD → `MemoryManager.write` requires `head`/`branch` args; CLI writes use the repo HEAD.
- `memory_index` must be rebuilt after external edits (`walk memory index`; also at `ON_PROJECT_START`).
