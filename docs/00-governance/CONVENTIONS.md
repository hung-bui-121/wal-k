# Engineering Conventions

These conventions exist so that code written by different models or people is
indistinguishable in structure and quality. They are not stylistic preferences; they are
acceptance criteria. Tooling enforces most of them (`ruff`, `mypy --strict`, `pytest`).

## 1. Repository layout

```
src/walk/                 kernel package (see docs/01-architecture/ARCHITECTURE.md)
  <module>/
    __init__.py           re-exports the module's public API only
    models.py             pydantic models for this module (public contracts)
    <feature>.py          implementation, one concern per file
    errors.py             module-specific exceptions (subclass walk.errors.WalkError)
tests/
  <module>/test_<feature>.py   mirrors src layout 1:1
  conftest.py                  shared fixtures (tmp repo, in-memory sqlite, fake adapters)
docs/                     planning + architecture (this folder tree)
scripts/                  dev tooling, git hooks
pyproject.toml            single source of project metadata, tool config
```

A story's "Files" section names every file it may create or modify. Touching files outside
that list requires a note in the commit body explaining why.

## 2. Python

- Python 3.12+. Full type hints on every function, method and attribute. `mypy --strict`
  with zero errors; `# type: ignore` requires a trailing reason and is reviewed.
- `ruff` with the config in `pyproject.toml` (line length 100, `select = ["ALL"]` with a
  short documented ignore list). `ruff format` is the only formatter.
- Public functions, classes and modules have docstrings (Google style). Private helpers
  may omit them.
- Dataclasses are not used for persisted or cross-module data; use pydantic v2 models.
  Enums are `enum.StrEnum`.
- No module-level mutable state. No singletons. Dependencies are injected through
  constructors; wiring happens in `walk.runtime.container` only.
- `asyncio` for all I/O that talks to providers, Git, Jira or Unity. Blocking subprocess
  calls go through `asyncio.create_subprocess_exec`. Never `time.sleep` in async code.
- Errors: raise subclasses of `WalkError`. Never swallow exceptions silently; log and
  re-raise or convert to a typed error. Every error path that can be hit in production has
  a test.
- Logging: `logging.getLogger(__name__)`, structured `extra={}` fields, no f-strings in
  log calls. The execution ledger, not logs, is the audit trail.
- Paths: `pathlib.Path` only. All filesystem writes go through `walk.persistence` or
  `walk.memory` helpers so they are atomic (write temp + rename).
- Time: `datetime.now(tz=UTC)` only; never naive datetimes. Serialized as ISO 8601.
- IDs: generated by `walk.persistence.ids` (`<PREFIX>-<zero-padded int>` for human-facing
  entities, ULID for ledger events). Never hand-roll IDs elsewhere.
- Secrets: read from environment variables or the OS keyring via `walk.runtime.secrets`.
  Never written to `.ai/`, the ledger, logs or test fixtures.

## 3. Tests

- `pytest` with `pytest-asyncio` (`asyncio_mode = "auto"`). Test file mirrors the source
  file. Test names: `test_<behavior>_<condition>` in plain words.
- Each story's acceptance criteria map 1:1 to test functions; the story lists the test
  names. A story is not done until every listed test exists and passes.
- Coverage: ≥ 90% lines for the module(s) a story touches; ≥ 85% overall. Measured with
  `pytest --cov=walk --cov-report=term-missing`.
- No network, no real providers in unit tests. Fakes live in `tests/fakes/` and implement
  the same `Protocol` as the real adapter. Integration tests that need real services are
  marked `@pytest.mark.integration` and skipped by default.
- Deterministic: no reliance on wall clock or random without injection (`Clock` and
  `IdGenerator` are injectable).

## 4. Documentation in code

- Every pydantic model field has a `description=`.
- Every state transition, hook and permission is declared in data (tables/enums), never
  only in prose or prompts (§53, §31, §32).
- When a story changes an interface in `docs/01-architecture/INTERFACES.md`, the story
  updates that document in the same commit.

## 5. Quality gate command

The single command that must pass before every commit:

```
uv run ruff format --check . && uv run ruff check . && uv run mypy src tests && uv run pytest
```

It is wrapped as `scripts/check.sh` (and `scripts/check.ps1`) once Epic 01 story E01-S01
lands. Until then, run the commands directly.

## 6. Things an implementer must never do

- Invent requirements. If the story is ambiguous, follow `IMPLEMENTATION-PROTOCOL.md` §4.
- Change a public interface without updating `INTERFACES.md` and the dependent stories.
- Skip or weaken a test to make the gate pass.
- Commit generated secrets, provider transcripts or `.ai/` content from a real game project.
- Add a dependency not listed in the story or `ADR-0001` without recording a new ADR.
