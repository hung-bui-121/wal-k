# Commit Policy

This policy is mandatory for every agent and every model that commits to this repository.
It is enforced mechanically by `scripts/git-hooks/commit-msg`.

## 1. Granularity

- One commit per completed **story** or **task**. Never bundle two stories.
- A commit must leave the repository green: lint, types and tests pass (see
  `DEFINITION-OF-DONE.md`). Never commit a half-finished story.
- After committing, **push immediately** to `origin` on the current branch. No approval is
  required for commit or push; both are part of finishing a story.

## 2. Message format

```
<type>: <subject>

<optional body>
```

| Type | Use for |
|---|---|
| `feat` | Any story/task that adds or changes behavior, code, configuration or schema |
| `bugfix` | Any story/task that fixes a defect |
| `docs` | Documentation-only changes (planning docs, ADRs, README) |
| `chore` | Tooling, CI, dependency bumps, repo hygiene with no behavior change |

Rules:

1. `type` is lowercase, followed by `: ` (colon, space). No scope parentheses.
2. `subject` is imperative mood, lowercase first letter, no trailing period, ≤ 72 characters.
3. The subject ends with the story/task ID in parentheses when one exists, e.g.
   `feat: add workflow transition table (E01-S04)`.
4. Body (optional) explains *why*, wraps at 72 columns, and may list requirement refs
   (`§53`) and evidence (test names, coverage).
5. **No attribution or signature lines of any kind.** Forbidden anywhere in the message:
   `Co-Authored-By`, `Signed-off-by`, `Generated with`, `Generated by`, any AI tool or model
   name. The hook rejects these.

## 3. Examples

```
feat: add Effort enum and effort resolution policy (E01-S07)

Implements §17–§19. Effective effort = max(role default, task complexity,
risk) clamped by remaining budget. Covered by tests/effort/test_policy.py.
```

```
bugfix: resume checkpoint after provider timeout (E01-S12)
```

```
docs: add epic 03 coding workflow stories
```

## 4. Branching

- `main` is the integration branch and is always releasable.
- MVP work (Stages 1–3) commits directly to `main`, one story per commit.
- From Stage 4 onward, or whenever two agents work in parallel, each story uses a branch
  `story/<ID>-<slug>` and a worktree; merge to `main` with `--no-ff` after review.

## 5. Hook installation

Run once per clone (the implementation protocol does this automatically):

```
git config core.hooksPath scripts/git-hooks
```
